      Pseudocode
      GREEDY-REGISTER
      

      sort requests by priority descending
for each request r:
    if prerequisites not met        → reject
    if credits + r.credits > max   → reject
    if overlaps existing meetings   → reject
    if section has no seats         → waitlist
    accept r; update credits, schedule, seats
      
          
      Pseudocode
      BACKTRACK with pruning
      

      search(i, credits, value):
    if i = n: record best solution; return
    if credits + remaining < min: return   // prune
    if value + remaining ≤ best:   return   // bound
    if course i fits (credits, no clash):
        include i; search(i+1, ...); undo i
    search(i+1, credits, value)    // exclude i
      
        
      
      
      
    
      
  
      
  
      Interval overlap rule: A and B clash when A.start < B.end and B.start < A.end. Back-to-back classes are allowed.
